03 / LAYOUT

三套版式，挑一套 — 同一套 UI 语言，三种组织方式

三台手机用的都是现有首页那套件：问候横幅（白→浅蓝渐变 + 品牌点 + 吉祥物）、KPI 卡（左图标右数值）、今日重点卡（灰底 + 26px 大数字 + 黑底主按钮）、常用功能宫格（40px 色块 + 角标）、名单行（风险色条 + 头像描边 + 三列指标）。差别只在怎么组织。 每台手机都能点 Tab / 按住左右拖 —— 切换动画就是校园资讯那套。

A · 四段分页 推荐
问候横幅常驻顶部，下面四段：概览 / 名单 / 节奏 / 分析。概览 = 原首页原样（KPI + 今日重点 + 常用功能 + 我的节奏），名单 = 原学生页列表原样。 优点：四个入口平级、边界清楚；和首页位的校园资讯用同一个分页组件，交互完全同感。风险：概览段偏长，首屏只能装到 KPI + 今日重点。
B · 首屏主导 + 二级子页 最贴近原话
默认就是现在的首页（一整条纵向流），学生名单收成底部一张摘要卡：3 条高危 +「看全部 42 人 ›」。点进去才是二级子页（整页推入，带返回键），班级分析同理。 优点：首页观感几乎不变，改动最小最安全；学生内容真的「降为二级子页」。风险：名单要两步才到，高频入口被埋深一层。
C · 双段（我的 / 班级） 折中
只分两段：我的（KPI + 今日重点 + 节奏 + 常用功能）/ 班级（名单 + 分析）。语义最清楚——先管自己今天的事，再看班上的人。 优点：左右滑一次就在「我」和「班」之间切换，名单一步可达。风险：「我的」段偏长，常用功能沉底。

05 / MOTION

子页切换动效 — 照搬校园资讯，不新造一套

1三段轨道 + 跟手

内容铺在同一条横向轨道上，位移只发生在轨道上，外层视口负责 overflow:hidden（裁切层不能跟着动，否则平移到 ±一屏时整页空白 —— 这是校园资讯里踩过的坑）。按下先不定轴，位移超 12px 才判定横向；横向手势归 JS，纵向仍交给页面滚动（touch-action: pan-y），边界按 0.35 阻尼回弹。

2点 Tab / 点入口：整页推入

不做「渐隐淡入」，而是把轨道瞬时挪到「目标页 ± 一屏」（关过渡），下一帧再归零 —— 视觉上就是目标页从侧边推入。这跟校园资讯 CampusPage.vue 的 slideToTab 完全一致；版式 B 的二级子页点「看全部 42 人 ›」走同一条路径，只是没有 Tab 条。

// 点 Tab / 点入口：瞬时错位 → 下一帧归零 track.style.transition = 'none' track.style.transform = `translate3d(${-(target*W) + dir*W}px,0,0)` void track.offsetWidth // 强制结算 track.style.transition = '' // 回到 200ms track.style.transform = `translate3d(${-target*W}px,0,0)`

3指示条与缓动曲线

下划线用 transform + width 驱动，200ms cubic-bezier(.22,.61,.36,1) —— 与轨道同一段曲线、同一时长，所以「页在动、条也在动」看起来是一件事。拖动时按页位移比例在相邻 Tab 之间插值（progress = idx - dx / W）并关掉过渡保持 1:1 跟手；松手吸附完成后再开过渡。这条曲线也是 teacher-ui.css 里的 --tui-ease，两端本来就共用。

RISK必须先解决的四个坑

  • 1手势打架：分页横向 Pointer 逻辑与 usePullRefresh、列表纵向滚动同屏。判轴阈值 ≥12px，且分页只挂在内容区、不挂吸顶头。
  • 2滚动位置：每段各自独立滚动，切回来要恢复原位；从长列表切回概览不能停在半空。
  • 3数据重复请求：概览与名单都用学生数据，合并后共用一次 getStudents，别让两个 panel 各拉一遍。
  • 4权限不只靠隐藏：资讯页的发布 / 撤回按钮前端隐藏之外，后端必须校验 role=teacher。
