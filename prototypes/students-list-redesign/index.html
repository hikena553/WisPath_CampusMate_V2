学生名单页 4 套重设方案

现状：搜索框 + 危机 chips + 白色通栏列表。信息只有一行「学院 · 成果N · 请假N」串联文本， 数字无法纵向比较，风险等级在列表里几乎不可见，筛选后也不知道剩几个。下面是 4 套方向不同的重设， 都基于现有设计令牌（#f2f3f5 底 / 白卡 / 发丝线 / 品牌蓝 #2563eb），可直接落地到 StudentsPage.vue。

1信息不可扫读「成果2 · 请假1」挤在一行灰字里，横向串读成本高
2风险不可见只有一个小小的 tag，高危学生和普通学生长得一样
3筛选无反馈chips 不带数量，点完不知道命中几条
4缺少排序42 人只能按固定顺序往下翻，找不到「最该聊的那个」

A · 指标对齐卡

把「成果 / 请假 / 评分」拆成三列固定宽度的数字，纵向扫一眼就是一张迷你表格；风险用左侧 3px 色条 + 头像描边表达，不额外占位。

  • 数字成列：36px 定宽度量列，tabular-nums，42 人也能纵向比较
  • 风险前置：左色条（红/橙/黄）+ 头像双环，扫读时第一眼命中高危
  • 零值弱化：成果 0 显示浅灰，避免「全是 0 也很吵」
  • chips 带计数：全部 6 / 高危 1 / …，点之前就知道有几条
  • 排序入口：搜索框右侧一个按钮，最近互动 / 风险 / 评分 / 姓名
适合：30–60 人班级的日常浏览。信息密度和可读性最平衡，改动量最小，风险最低。

实现要点

B · 风险分组吸顶

列表按风险等级自动分组，组头吸顶并带人数与颜色；点 chips 变成单组过滤。评分右对齐成独立一列，最该聊的人永远在最上面。

  • 组头即结论「需重点关注 1 · 持续观察 1 · 状态平稳 3」一眼看清班级风险结构
  • 吸顶导航：滚动时组头固定，长名单不迷失位置
  • 分段器排序：按风险 / 按评分 / 按姓名，三种工作方式随时切
  • 评分单列：右对齐定宽数字列，高低分用色区分
适合：需要「危机处置优先」的班主任视角。缺点是行高略大，50 人以上翻页更累。

实现要点

C · 风险优先工作台

顶部四个数字磁贴本身就是筛选器（点「高危 1」即过滤），下方把风险学生展开成处置卡：带响应时效进度与「去处置」按钮，普通学生压缩成两行。

  • 统计即筛选：磁贴 = tab，省掉一层 chips，减少一次点击
  • 风险带行动：SLA 进度条 + 去处置，名单页直接完成任务闭环
  • 强弱分层：告警卡厚、普通行薄，视觉重心自动落到该处理的人身上
  • 一处两用：既是名单，也是当天的工作清单
适合：预警量大、要求「发现即可处置」的场景。缺点是信息密度最高，普通学生的次要指标被折叠。

实现要点

    - +new Date(at)) / 3.6e6
  return Math.min(100,
    h / SLA_HOURS * 100)
}

D · 紧凑高密度表

去掉卡片、只留发丝线和表头，46px 一行，一屏 12 人。表头标注「成果 / 请假 / 评分」，把手机当表格用，靠列对齐而不是文案取胜。

  • 一屏 12 人：46px 行高 + 表头，翻页次数直接砍半
  • 表头即语义：数字列有表头，不用每行重复「成果 2 请假 1」
  • 风险双编码：圆点 + 姓名字色（红/橙），不额外占列宽
  • 去掉头像：姓名与学院同行，行高从 60px 压到 46px
  • 零值弱化：成果 0 用浅灰，避免「全是 0」干扰读数
适合：大班（80–200 人）、以「找人」为主的高频场景。缺点是情感温度低，学生个体感弱。
