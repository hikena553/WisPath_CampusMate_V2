# 数据库上云 · 云服务器部署与数据迁移

本文档对应「云服务器自建整套 + 保留本地数据」方案：把 MySQL、后端、前端一起跑在
一台云服务器上，并把本地 SQLite（`backend/campus_mate.db`）里的真实数据完整搬过去。

---

## 0. 先明确三件事

1. **代码不用改**。`docker-compose.yml` 已经编排好 MySQL 8 + backend + frontend，
   后端也早就支持 MySQL（`pymysql` 在依赖里）。
2. **schema 不用搬**。云端首次启动时 `alembic upgrade head` 会自动建出全部表。
   只需要搬「行数据」。
3. **两个 `.env` 别搞混**（这是最容易踩的坑）：

| 文件 | 谁读它 | 作用 |
|---|---|---|
| 项目根目录 `.env` | docker compose | 提供 MySQL 密码、SECRET_KEY、LLM 密钥等，用于**变量替换** |
| `backend/.env` | 本地开发时的 Python | 只在本地直接跑 `python main.py` 时生效，**已被 `.dockerignore` 排除，不会进镜像** |

所以服务器上**只需要根目录 `.env`**，`backend/.env` 不用传上去。

## 1. 服务器准备

### 规格建议

| 项 | 建议值 | 说明 |
|---|---|---|
| CPU / 内存 | 2 核 4G 起 | MySQL 约 0.5~1G，后端 Python + jieba 约 1G，留余量 |
| 系统盘 | 40G+ | 镜像 + 上传文件 |
| 系统 | Ubuntu 22.04 / 24.04 LTS | 下面命令按此编写 |
| 带宽 | 3M 起 | 前端产物不大，够用 |

阿里云/腾讯云的「轻量应用服务器」就够用，不必上 ECS/CVM 通用型。

### 安全组 / 防火墙

放通 **22（SSH）**、**80（HTTP）**、**443（HTTPS）**。
**不要**放通 3306 —— 数据库只在 compose 内网可达，不对外暴露。

### 初始化

```bash
# 时区（否则日志和数据时间都是 UTC）
sudo timedatectl set-timezone Asia/Shanghai

# swap：2C4G 机器上 MySQL + Python 同时跑，没 swap 容易 OOM 被杀
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

# Docker（含 compose 插件）
curl -fsSL https://get.docker.com | sudo sh -s -- --mirror Aliyun
sudo systemctl enable --now docker

# 本机防火墙
sudo ufw allow 22/tcp && sudo ufw allow 80/tcp && sudo ufw allow 443/tcp
sudo ufw --force enable
```

## 2. 上传代码与配置

```bash
sudo mkdir -p /opt && cd /opt
sudo git clone <你的仓库地址> smart-campus
cd smart-campus

cp .env.example .env

# 生成 SECRET_KEY（必须 ≥32 位）
python3 -c "import secrets; print(secrets.token_hex(32))"

vim .env
```

`.env` 里**必须**改的项：

```ini
MYSQL_ROOT_PASSWORD=<强随机密码>
MYSQL_PASSWORD=<强随机密码>
SECRET_KEY=<上一步生成的 64 位 hex>
```

LLM 相关配置请**以本地 `backend/.env` 为准逐项抄过来**。根目录 `.env.example`
里的 `LLM_BASE_URL` / `LLM_MODEL` 可能与当前开发环境不一致，直接照抄模板会导致
线上换成了另一套模型、AI 行为对不上。

> ⚠️ 密码含 `@ : / ?` 等字符时必须 URL 编码。`DATABASE_URL` 由 compose 用
> `${MYSQL_USER}:${MYSQL_PASSWORD}` 拼装，明文特殊字符会让连接串解析错位，
> 例如 `p@ss` 要写成 `p%40ss`。

## 3. 首次启动（自动建表 + 种子数据）

```bash
cd /opt/smart-campus
docker compose up -d --build        # 首次构建前端约 3~5 分钟
docker compose ps                   # 三个服务都应为 Up / healthy
docker compose logs -f backend      # 看到「应用启动完成」即可 Ctrl+C
```

启动顺序由 compose 保证：`db` 健康 → `backend` 跑 `alembic upgrade head` →
应用 lifespan 再跑一次迁移 + `seed` 幂等种子数据 → `frontend` 提供页面。

此时库里已经有一套演示数据（admin / t1001 / 2024001 等）。

浏览器打开 `http://<服务器IP>/` 能看到登录页，说明基础链路通了。
**先别急着登录**，下一步会把种子数据整体替换成你的真实数据。

## 4. 迁移本地数据（核心步骤）

### 4.1 在本地导出

Windows 下在项目根目录执行（用项目自带的 venv，别用系统 Python）：

```bash
cd backend
.venv\Scripts\python.exe scripts\db_migrate.py export --out ..\out\db_dump.json
```

预期输出：

```
[export] 共 80 张表 / 1350 行，文件 428.0 KB
```

这个 JSON 里包含每张表的列名和全部行数据，可移植、可重复导入。

### 4.2 上传到服务器

```bash
scp out/db_dump.json root@<服务器IP>:/opt/smart-campus/
```

### 4.3 停掉后端再导入

后端有 5 个后台周期任务会持续写库，导入过程中抢写会导致数据错乱，务必先停：

```bash
cd /opt/smart-campus
docker compose stop backend
ls -lh db_dump.json          # 确认文件在项目根目录，与 docker-compose.yml 同级
```

> ⚠️ **不要把 dump 文件用 `docker compose cp` 复制进容器再 `docker compose run`。**
> `run --rm` 启动的是一个**全新容器**，不是 `cp` 操作的那个容器，文件不在里面，
> 脚本会直接报 `FileNotFoundError`。正确做法是用 `-v` 把宿主机文件挂载进去
> （下面 4.4 / 4.5 已按此写）。

### 4.4 干跑一遍，只统计不落库

```bash
docker compose run --rm --entrypoint python \
  -v "$PWD/db_dump.json:/app/db_dump.json:ro" \
  backend scripts/db_migrate.py import --dump /app/db_dump.json --dry-run
```

`--entrypoint python` 是必须的：镜像默认入口是 `docker-entrypoint.sh`，
不加它的话参数会被吞掉、直接去启动 uvicorn。
容器内的 `DATABASE_URL` 由 compose 注入，所以不用手动传 `--target`。

确认输出里没有 `[skip]` 行，以及计划写入行数与本地一致。

### 4.5 正式导入

```bash
docker compose run --rm --entrypoint python \
  -v "$PWD/db_dump.json:/app/db_dump.json:ro" \
  backend scripts/db_migrate.py import --dump /app/db_dump.json
```

脚本做的事：

1. 逐表 `DELETE` 目标表（保证主键 id 与本地一致，登录态、外键指向都不会错位）
2. `FOREIGN_KEY_CHECKS=0` 全程关闭，避免插入顺序引起的外键报错
3. JSON 列先把字符串 `json.loads` 成对象再写入，避免双重编码
4. 日期字符串显式解析成 datetime，空串转 NULL
5. 全部成功才提交，中途报错整体回滚

### 4.6 核对

```bash
docker compose run --rm --entrypoint python \
  -v "$PWD/db_dump.json:/app/db_dump.json:ro" \
  backend scripts/db_migrate.py verify --dump /app/db_dump.json
```

期望输出：

```
[verify] 核对 39 张非空表，行数全部一致 ✅
```

### 4.7 重新拉起后端

```bash
docker compose up -d backend
docker compose logs -f backend
```

`seed` 是幂等的（`get_or_create`），发现数据已存在会跳过，不会覆盖你刚导入的数据。

## 6. 备份与回滚

**导入前**先在服务器上留一份快照，出问题能立刻退回去：

```bash
docker compose exec -T db sh -c \
  'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction --routines "$MYSQL_DATABASE"' \
  | gzip > backup_before_import_$(date +%F_%H%M).sql.gz
```

日常备份加进 crontab：

```bash
# 每天 03:30 备份，保留 14 天
30 3 * * * cd /opt/smart-campus && docker compose exec -T db sh -c 'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction "$MYSQL_DATABASE"' | gzip > /opt/backup/db_$(date +\%F).sql.gz && find /opt/backup -name 'db_*.sql.gz' -mtime +14 -delete
```

恢复：

```bash
gunzip -c backup_before_import_xxxx.sql.gz | docker compose exec -T db sh -c \
  'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" "$MYSQL_DATABASE"'
```

代码回滚：`git checkout <上一个commit> && docker compose up -d --build`。
注意迁移不可逆时不要轻易 `alembic downgrade`。

## 7. 数据一致性说明（迁移时会看到的两类「差异」）

跑 `verify` 或自己做比时，可能看到这两种情况，**都不影响业务**：

| 现象 | 原因 | 影响 |
|---|---|---|
| `feed_sources.filter_kw` 本地是文本 `null`、云端是 SQL NULL | 旧 SQLite 写入时把 JSON null 存成了字符串 | 无。ORM 读出都是 `None`，反而更正确 |
| 日期少了微秒（`12:15:08.255007` → `12:15:08`） | MySQL `DATETIME` 默认无小数精度 | 无。仅影响同一秒内多条记录的排序粒度 |

另外本地有一张 `campus_figures` 表（5 行）在迁移脚本里已被废弃、目标库没有，
导入时会明确提示并跳过，属于预期行为。

## 8. 常见问题

**backend 启动即退出，日志里有 `1044 Access denied`**
旧版 `_ensure_database()` 会无条件执行 `CREATE DATABASE`，而容器里的应用账号
只有库级权限。本次已修复为「先探测再建库」，拉最新代码重建即可：
`git pull && docker compose up -d --build`。

**`Access denied for user 'campus'@'%'`**
`.env` 里的 `MYSQL_PASSWORD` 在数据卷初始化后才改 —— MySQL 官方镜像**只在首次
初始化时**应用 `MYSQL_PASSWORD`。改密码要走 `ALTER USER`，或者
`docker compose down -v` 重建（会清空数据，谨慎）。

**连不上数据库 / 端口错位**
检查密码是否 URL 编码；检查 `.env` 里是否有多余空格或引号。

**内存被打满**
先确认 swap 已启用（`free -h`），再把 `UVICORN_WORKERS` 保持为 1
（周期任务在进程内调度，多 worker 会重复执行任务）。

**时间差 8 小时**
容器默认 UTC。compose 里可给各服务加 `TZ: Asia/Shanghai`，
MySQL 侧用 `--default-time-zone=+08:00`。

**HTTPS**
nginx 目前只监听 80。生产建议在前面加一层云厂商负载均衡终结 TLS，
或用 Caddy / certbot 自动续期，证书挂载点 `./deploy/certs` 已在 nginx.conf 中预留。
