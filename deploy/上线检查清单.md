# 上线检查清单

> 面向「马上要上线」的执行清单。按顺序做，每步都有验证动作。
> 完整背景与原理见 [上云部署与数据迁移.md](./上云部署与数据迁移.md) 与 [README.md](./README.md)。

---

## 阶段 0：本地出库（在开发机做）

- [ ] **代码已提交并推送到远程**
      ```bash
      git status                 # 工作区应为干净
      git push origin develop    # 服务器 clone 的是远程代码，不 push 等于没改
      ```
- [ ] **后端导入冒烟**
      ```bash
      cd backend && .venv/Scripts/python.exe -c "import app.main"
      ```
- [ ] **前端构建零报错**
      ```bash
      cd frontend && npm run build
      ```
      > 沙箱/受限环境如遇 Temp 权限报错，先 `mkdir -p .tmpbuild`，
      > 再带 `TMP=TEMP=TMPDIR=$PWD/.tmpbuild` 前缀运行，跑完删掉。
- [ ] **数据导出**（要搬本地数据时）
      ```bash
      cd backend && .venv/Scripts/python.exe scripts/db_migrate.py export --out ../out/db_dump.json
      ```
- [ ] **确认 `.env` 没有进版本库**
      ```bash
      git check-ignore -v .env       # 应输出 .gitignore:50:.env
      ```

## 阶段 1：服务器初始化

- [ ] 规格 ≥ 2 核 4G，系统盘 ≥ 40G，系统 Ubuntu 22.04/24.04
- [ ] **安全组**：只放通 22 / 80 / 443。**绝不放通 3306**（数据库只在 compose 内网可达）
- [ ] 时区
      ```bash
      sudo timedatectl set-timezone Asia/Shanghai
      ```
- [ ] swap（2C4G 不加 swap，MySQL + Python 同时跑容易 OOM 被杀）
      ```bash
      sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile
      sudo mkswap /swapfile && sudo swapon /swapfile
      echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
      free -h                     # 确认 Swap 行有 2.0Gi
      ```
- [ ] Docker + compose 插件
      ```bash
      curl -fsSL https://get.docker.com | sudo sh -s -- --mirror Aliyun
      sudo systemctl enable --now docker
      docker compose version
      ```
- [ ] 本机防火墙
      ```bash
      sudo ufw allow 22/tcp && sudo ufw allow 80/tcp && sudo ufw allow 443/tcp
      sudo ufw --force enable
      ```

## 阶段 2：部署

- [ ] 拉代码
      ```bash
      sudo mkdir -p /opt && cd /opt
      sudo git clone <仓库地址> smart-campus && cd smart-campus
      ```
- [ ] **配置 `.env`**（关键步骤，逐项核对）
      ```bash
      cp .env.example .env && vim .env
      ```
      必改项：

      | 变量 | 要求 |
      |---|---|
      | `MYSQL_ROOT_PASSWORD` | 强随机，**纯字母数字**（含 `@ : / ?` 需 URL 编码，否则连接串解析错位） |
      | `MYSQL_PASSWORD` | 同上 |
      | `SECRET_KEY` | `python3 -c "import secrets; print(secrets.token_hex(32))"`，≥32 位 |

      LLM 四项必须与本地 `backend/.env` **逐项一致**，漏写一项就会静默换成另一套模型：
      ```ini
      LLM_BASE_URL=https://maas.qianwenaiapi.com/compatible-mode/v1
      LLM_MODEL=qwen3.8-27b
      LLM_AGENT_MODEL=qwen3.8-27b
      LLM_API_KEY=<本地同值>
      DASHSCOPE_API_KEY=<本地同值>
      ```

- [ ] 构建启动（首次前端构建约 3~5 分钟）
      ```bash
      docker compose up -d --build
      ```
- [ ] 三个服务全部 healthy
      ```bash
      docker compose ps          # db / backend / frontend 均应为 Up (healthy)
      docker compose logs -f backend   # 看到「应用启动完成」即 Ctrl+C
      ```
- [ ] 健康检查
      ```bash
      curl -s http://127.0.0.1/api/health
      # 期望 status=ok，database 字段正常
      ```
- [ ] 浏览器打开 `http://<服务器IP>/` 能看到登录页

## 阶段 3：数据迁移（仅当要搬本地数据）

> 全新部署可跳过；此时库里只有种子演示数据。

- [ ] 上传数据包到**项目根目录**（与 docker-compose.yml 同级）
      ```bash
      scp out/db_dump.json root@<服务器IP>:/opt/smart-campus/
      ```
- [ ] **先备份当前库**（导入会先清空目标表）
      ```bash
      docker compose exec -T db sh -c \
        'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction --routines "$MYSQL_DATABASE"' \
        | gzip > backup_before_import_$(date +%F_%H%M).sql.gz
      ```
- [ ] 停后端（有 5 个周期任务在写库）
      ```bash
      docker compose stop backend
      ```
- [ ] 干跑 → 正式导入 → 核对（**注意 `-v` 挂载，不要用 `docker compose cp`**）
      ```bash
      docker compose run --rm --entrypoint python \
        -v "$PWD/db_dump.json:/app/db_dump.json:ro" \
        backend scripts/db_migrate.py import --dump /app/db_dump.json --dry-run

      docker compose run --rm --entrypoint python \
        -v "$PWD/db_dump.json:/app/db_dump.json:ro" \
        backend scripts/db_migrate.py import --dump /app/db_dump.json

      docker compose run --rm --entrypoint python \
        -v "$PWD/db_dump.json:/app/db_dump.json:ro" \
        backend scripts/db_migrate.py verify --dump /app/db_dump.json
      ```
- [ ] 拉起后端
      ```bash
      docker compose up -d backend
      ```
- [ ] 用**本地原有账号**登录，确认对话记录、课表、通知、收藏都在

## 阶段 4：上线后必做

- [ ] **改掉所有初始密码**。种子数据会建出下列账号，密码是公开的：

      | 账号 | 初始密码 | 角色 |
      |---|---|---|
      | admin | admin123 | 管理员 |
      | t1001 ~ t1007 | 123456 | 教师 |
      | 2024001 等学号 | 123456 | 学生 |

      > 这条优先级最高。默认密码进了公网，等于把管理后台挂在门外。
- [ ] 管理员改用专用账号，停用默认 `admin`
- [ ] 配每日备份 cron
      ```bash
      sudo mkdir -p /opt/backup
      # 每天 03:30 备份，保留 14 天
      30 3 * * * cd /opt/smart-campus && docker compose exec -T db sh -c 'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction "$MYSQL_DATABASE"' | gzip > /opt/backup/db_$(date +\%F).sql.gz && find /opt/backup -name 'db_*.sql.gz' -mtime +14 -delete
      ```
      > 上传文件在 `uploads_data` 卷里，也需一并备份，否则头像/公告图恢复不回来。
- [ ] 验证时区：新建一条日程/通知，确认时间与本地一致（差 8 小时说明 TZ 没生效）
- [ ] 验证真实客户端 IP：登录页连续输错密码，观察日志里的 IP 是否为你的公网 IP
      而不是 nginx 内网地址（`172.x` / `10.x`）。若是内网 IP，说明代理头未生效。

## 阶段 5：HTTPS

**前置条件（缺一不可）**：

- [ ] 已有域名，A 记录解析到本机公网 IP，且已生效
      ```bash
      ping <域名>          # 应返回本机公网 IP
      ```
- [ ] 安全组放通 80 与 443

> ⚠️ Let's Encrypt **不对公网 IP 签证书**。只有 IP 时走不了这一步，
> 只能自签 —— 而自签证书下浏览器会拒绝麦克风权限，语音通话功能等于不可用。

**执行**（在项目根目录）：

```bash
chmod +x deploy/enable_https.sh
./deploy/enable_https.sh <域名> <邮箱>
```

脚本做的事：webroot 模式申请证书（**前端不停机**）→ 把证书同步为固定文件名
`deploy/certs/{fullchain,privkey}.pem` → 自动把 `.env` 的 `NGINX_CONF` 切到
`./deploy/nginx.ssl.conf` → 重建 frontend 容器。

- [ ] 验证
      ```bash
      curl -sI https://<域名> | head -1     # 期望 HTTP/2 200
      docker compose logs --tail=20 frontend  # 无证书相关报错
      ```
- [ ] 浏览器打开 `https://<域名>/`，确认地址栏是小锁、无告警
- [ ] 访问 `http://<域名>/`，确认自动 301 跳到 https
- [ ] **验证麦克风**：进语音通话页，确认浏览器弹出麦克风授权（不弹 = 证书链有问题）
- [ ] 配证书续期（90 天有效，到期不续站点直接不可访问）
      ```bash
      sudo crontab -e
      # 每天 04:30 检查续期
      30 4 * * * cd /opt/smart-campus && ./deploy/enable_https.sh --renew >> /var/log/certbot-renew.log 2>&1
      ```

> 已启用 HTTPS 后，`.env` 里 `NGINX_CONF` 应保持 `./deploy/nginx.ssl.conf`，
> 不要改回 HTTP 版，否则站点会退回明文。

## 已知事项（非阻塞，了解即可）

| 项 | 说明 |
|---|---|
| 前端主包偏大 | `index-*.js` 约 1.1MB（gzip 384KB），移动端首屏偏慢。可后续做 manualChunks 拆分，不影响功能 |
| `UVICORN_WORKERS` 必须为 1 | 周期任务在应用进程内调度，多 worker 会重复执行 |
| `AUTO_MIGRATE` 单机保持 true | 多副本部署须改 false，迁移移到发布流水线单独执行 |
| 容器时区 | 已在 compose 中统一注入 `TZ=Asia/Shanghai`，MySQL 侧为 `+08:00` |
| 日志轮转 | 已按服务限制 `max-size` / `max-file`，避免写满系统盘 |

## 回滚

```bash
# 代码回滚
git checkout <上一个commit> && docker compose up -d --build

# 数据回滚
gunzip -c backup_before_import_xxxx.sql.gz | docker compose exec -T db sh -c \
  'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" "$MYSQL_DATABASE"'
```

> 迁移不可逆时不要轻易 `alembic downgrade`。
