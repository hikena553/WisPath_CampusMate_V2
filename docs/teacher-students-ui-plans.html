学生页 UI 重设计 · 三选一

学生页：从「平铺名单」到「该先找谁」

现有界面是搜索 + 五个危机筛选项 + 一列等高的学生卡，问题不在于难看，而在于它只回答了「我有哪些学生」，没回答「我现在该找谁」。 下面三个方案都借用了成熟开源/商业产品的成熟列表范式，各自代表一种完全不同的产品判断。左右滑动查看，选一个我再落地成 Vue 页面。

三个方案怎么选

没有绝对最优，取决于你打开学生页时的第一个动作是什么

维度方案 A 分诊队列方案 B 数据表方案 C 名册磁贴
打开页面第一反应 「今天先找谁」「这批人整体什么情况」「这个人在哪」
一屏可见人数 5~6 人（但全是重点） 8~10 人 6~9 人
能否直接操作 能，每条带「联系/约谈/查看」 不能，须点行进详情 不能，须点卡片进详情
后端改动 需加 triage 分组字段 零改动 需确认 avatar 覆盖率
学生规模适配 100 人以上最佳任意规模60 人以内最佳
主要风险 分组规则不准则整页失真手机上列少，信息要取舍没头像时辨识度反而下降
