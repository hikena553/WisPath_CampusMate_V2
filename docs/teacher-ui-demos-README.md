## 零、移动端子页：三套样式（最新，建议先看这份）

`teacher-mobile-ui-styles-demo.html` —— 覆盖全部 13 个功能子页（今日重点 / AI 洞察 / 学生档案 / 审批 / 预警 / 关怀中心 / 家校沟通 / 成长档案 / 问卷互评 / 查课表 / 我的课堂 / 我的成长 / 公告），每页压到 1 屏内。

三套样式共用**同一套信息骨架**，所以差异是纯视觉 + 容器形态，换成不是重写：

| 样式 | 语言 | 适合 | 代价 |
|---|---|---|---|
| **A · Clarity** | 清爽白、AI 卡置顶、单列 60px 行 | 13 页默认皮肤，一盯一整天 | 最常规，AI 存在感靠紫色卡撑 |
| **B · Paper** | 暖纸底、衬线标题、双列卡片、AI 便签 | 关怀 / 成长档案 / 家校沟通 | 密度低 15%，深色模式要另做 |
| **C · Console** | 深色、等宽数字、左侧状态条、一屏 6–8 条 | 预警 / 审批这类高压扫读页 | 白天户外可读性差 |

每页的设计约定（这也是「内容不长」的解法）：

1. **顶部第一块永远是 AI 结论**：一句话说清「有几件事、我做了多少、剩几件要你决定」，带 1–2 个可点动作；
2. **中间只放需要人判断的东西**：能自动处理的收成一张汇总卡（如审批「4 条材料齐全 → 通过」），不逐条列；
3. **长的东西收进抽屉**：谈心提纲、AI 草稿、评语都是点开才出现；
4. **底部主按钮永远是 AI 动作**（“一键通过 4 条”“预批 12 份，我只复核 2 份”），右侧留分享。
5. 结尾一行 `AI 还注意到…` 放本页最有价值的横向洞察，同时把短页面的留白坐实。

怎么用：左侧切页面 / 切样式；右上角「三套并排 ↔ 单套放大」；审批页可真的通过/驳回，关怀页可展开提纲，家校页可换语气，问卷可替换题目，课堂可预批，全部有状态变化。

## 一、学生页：从「平铺名单」到「该先找谁」

### 现在的问题
搜索框 + 五个危机筛选 + 一列等高学生卡。它只回答「我有哪些学生」，没回答「我现在该找谁」。

### 三个方案

**A · 分诊队列**（Linear Inbox / GitHub Triage / PagerDuty）
按「该做的事」分组：必须今天处理 / 这周要跟进 / 状态平稳（折叠）/ 本月已闭环。
- 解决了：不用自己比对，分组替你判断完了
- 代价：分组规则要写死，规则错了就是错的分组
- 适合：学生多（≥100）、真正按风险响应的辅导员

**B · 数据表**（Notion Database / Airtable / GitHub Issues Table）
一屏 14~18 人，点列头按评分 / 预警 / 成长排序。
- 解决了：密度。排序后「谁最差 / 谁最好」一眼可见
- 代价：不告诉你「为什么该找他」，理由被压进详情
- 适合：习惯自己排序找规律、日常做横向对比的老师

**C · 名册磁贴**（iOS 通讯录 / BambooHR / Vercel Team）
两列磁贴，底色和描边跟着危机等级走。
- 解决了：认人。磁贴比表格更像名册，亲和力最强
- 代价：密度最低，18 人要滚 9 屏
- 适合：带班 30~60 人、重视「认识每个学生」的小班辅导员

### 建议：A 为主，B 作为 A 的「全部」页
你的定位是「育人 + 辅导员工作台 + 个人工作台」，三者里辅导员工作台最需要一个「现在是哪个学生出事了」的入口。
A 和「今日重点」是同一种语言（待办队列），用户不用切换心智；B 的价值在「全部 42 人」这个场景才成立。
所以：**默认 A 的分诊视图，切到「全部」时降级成 B 的数据表**——一套页面两种密度，比三选一更实用。

### 分诊规则（这是 A 的核心，也是最该被质疑的地方）
不按危机等级单维度分组，而是「等级 + 多久没联系」：

```
closed                    → 本月已闭环
severe                    → 必须今天处理
moderate 且 失联 ≥7 天    → 必须今天处理
moderate                  → 这周要跟进
mild 且 失联 ≥7 天        → 这周要跟进
mild 且有未闭环事项       → 这周要跟进
其余                      → 状态平稳（折叠）
```

18 人跑出来的比例：今天 5 / 本周 3 / 平稳 8 / 已闭环 2。
**反面教训**：第一版把所有「有理由」的人都丢进待跟进，13 / 18 都成了待处理，等于没分诊。

## 二、功能页：同一个页面，三种「信息怎么摆」

### 现在的问题
每个功能页都是超长单列流水，手机上要滚十几屏。

| 页面 | 行数 | 病症 |
|---|---|---|
| 审批管理 | 2107 | 移动端滚 12 屏以上 |
| 人文关怀 | 1794 | 8 个 section 平铺无导航 |
| 家校沟通 | 1026 | 无分区，全靠滚动 |
| 成长档案 | 811 | 5 类记录混排 |
| 公告 / 问卷 | 704 / 598 | 相对正常，只需微调 |

### 三个方案

**1 · 顶部 Tab**（Linear / GitHub Issues / 飞书审批）
把长页切成几段。2107 行拆成 3 个 Tab，每个约 1.5 屏。
- 代价：Tab 之间互相看不见；超过 5 个 Tab 横向塞不下
- 改造成本：最低（加个 Tab 容器）

**2 · 主从分栏**（Gmail / 钉钉审批 / Outlook）
左边挂列表，右边一直是详情，不用「点进详情再退回列表」。
- 代价：手机只有 390px 宽，两栏都窄
- 改造成本：中（要拆列表 / 详情组件）

**3 · 工作台卡片**（Vercel Dashboard / Sentry / Datadog）
先看总量再进细节。
- 代价：卡片只能给摘要，真正办事还得点进去——**不适合当功能页**
- 改造成本：高（要重新设计聚合接口）

### 建议：方案 1 打底，方案 2 只给审批用
6 个页面本来就不在同一复杂度量级：公告 704、问卷 598 只需微调，真正要治的是审批 2107 和关怀 1794。
- 6 个页面统一用方案 1 的 Tab 骨架（改动小、手机上稳）
- **审批管理单独做成方案 2 的主从分栏，且只在 ≥768px 生效**，手机自动降级成方案 1
- 方案 3 别用来改功能页，它更适合「今日重点」——那里本来就是工作台

## 三、怎么用这两份演示

打开后顶部有「三栏并排 / 单方案放大」切换。建议先并排看差异，再单方案放大试操作：

**学生页能试的**
- 搜索框输入「林」→ 三个方案都真过滤
- 点高危筛选、点列头排序 → 真排序
- 点任何一个学生 → 右侧拉出详情抽屉（指标 / 为什么关注 / 技能兴趣 / 最近联系）
- 方案 A 点「状态平稳」的折叠行 → 展开全部

**功能页能试的**
- 方案 1 点顶部 Tab 切待处理 / 已通过 / 已拒绝
- 方案 2 点左侧列表任意一条 → 右侧详情整体跟着换
- 任意方案点「通过」或「拒绝」→ 那条真的从待处理列表消失，徽标跟着减
- 方案 3 点卡片 → 进对应详情

数据字段全部对齐真实后端（`crisis_level`、`score`、`growth_count`、`leave_type`、`ServiceTicket.type`、`status`），
所以选定后能直接照着接现有接口，不需要改数据结构。
