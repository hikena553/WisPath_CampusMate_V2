## 一、落地方式（先看这条，避免下轮重复讨论）

- **只改移动端**：每个页面用 `v-if="isMobile"` 分出移动分支，桌面端结构一行不动。
- **共用一套设计系统**：`frontend/src/styles/teacher-mobile-kit.css`（`tm-` 前缀，592 行），
  在 `main.ts` 里全局引入一次。版式、色板、AI 卡、行、tag、热力格、题卡、对话气泡都在里面。
- **色板**：冷色调（`#f3f6fb` 底 / 白卡 / `#2f6df6` 主色 / `#5b5bd6` AI 紫 / 红=空档·冲突）。
  所有变量挂在 `.tm-page` 上（`--tm-*`），不会和 `teacher-ui.css` 的 `--tui-*` 打架。
- **数据一律用真实接口**，没有的就不编（见「数据缺口」）。

## 三、实测提醒（下轮别踩）

- **AI 洞察接口慢**：`/agent/proactive` 有时要 6~10s，页面先显示骨架屏。
  巡检脚本会等 `.agent-loading` 消失（上限 15s）再截图，别在 2~3s 时误判成「页面空」。
- **我的课堂热力块受数据门槛**：`v-if="isMobile && stats"`，dev 库 t1001 全学期 `courses = 0`，
  移动端和桌面端一样显示「本学期暂无你任教的课程」，热力块没机会渲染（不是 bug）。
- **学生档案要先进二级子页**：移动端工作台首屏是 `HomeMobileBoard`，学生名单在
  `rosterSubPage` 里（点 WorkloadCard 的「档案」按钮进）。巡检脚本已内置这一步
  （`PAGES` 里的 `open: '.wb-more:has-text("档案")'`），手工看的时候别漏。
- **登录接口有频率限制**，短时间连跑会 429；脚本内置等 30s 重试。

## 五、数据缺口（改之前先确认，别在前端编）

| 页面 | 缺口 | 现在怎么处理的 |
|---|---|---|
| 我的课堂 | 出勤没有「按周/按天」历史，`attendance/stats` 只给每人汇总 | 热力按「人」着色，不假装有周次热力图 |
| 关怀中心 | 没有「谈心」独立表，只有 `care_events` 的 `event_type` | 节律按所有关怀事项计数，不区分谈心/家访 |
| 家校沟通 | `ContactLog` 没有 direction 字段 | 只渲成「我记录的沟通」气泡，不假装双向聊天 |
| AI 洞察 | `ProactiveAction` 没有 student_name | 卡片标题用 `title`，副标题「信号类型 · 学生 #id」 |
| 问卷 | 没有「建议」的 AI 打分 | 建议仍走 `AiDraftField` 的模板草稿 |
| 学生档案 | 后端没有 `triage_bucket` | 前端只读 `crisis_level` 临时推导，脚注里写明 |
| 预警 | 剩余小时数靠 `follow_up_date` 推算 | 没有随访日期的按「已等待天数」排在后面 |
| 成长档案 | 能力条口径取自学生端同名指标 | 竖线用全班均值，满格用全班最高；缺数据就不画 |

## 六、复跑方式

巡检脚本固化在 `scripts/mobile-check.cjs`（仓库根目录，用根 `node_modules` 里的 playwright）。

```bash
# 前提：后端 8000 + vite 5173 已启动

node scripts/mobile-check.cjs                    # 跑 8 页（group=done）
node scripts/mobile-check.cjs --all              # 13 页全跑
node scripts/mobile-check.cjs --only=care,ai     # 只跑指定页
node scripts/mobile-check.cjs --user=t1001 --pass=123456
node scripts/mobile-check.cjs --width=414 --height=896   # 换机型

# 类型 / 构建
cd frontend && npx vue-tsc --noEmit && npx vite build
```

它做四件事：打开二级子页、等骨架屏消失后截图、查 `pageerror` / `console.error`、
查横向溢出并点名越界元素；有问题时退出码 1，可直接接 CI。

**产物**：`tmp_m_ui/<key>.png`，超过一屏的页面分段出 `<key>_2.png / _3.png / _4.png`
（移动端是整页锁高 + 内部滚动，`fullPage` 只能拍到一屏，所以按滚动容器分段）。

## 七、写移动端时的固定套路（下轮照抄）

1. 页面里加 `<div v-if="isMobile" class="tm-page">…</div>`，桌面结构一行不动；
2. 版式只用 `teacher-mobile-kit.css` 里的 `tm-` 类，确实不够才在组件里写 scoped 补（类名仍以 `tm-` 开头）；
3. 卡片顺序固定为：**AI 结论条 → 关键数字 → 分段 → 列表 → AI 观察/依据脚注**；
4. 折叠/展开类区块不要写死默认展开档位，数据到位后自动展开「第一个有人的档」；
5. 数据只用真实接口，缺的字段在「数据缺口」里登记，不在前端编；
6. 改完跑 `scripts/mobile-check.cjs --only=<key>`。
