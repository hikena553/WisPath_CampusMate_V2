核心结论（v2 更新）

闭环问题已基本解决；教师端的下一道关卡，是「数字教育」与「辅导员个人成长」两个维度不够突出。

初版诊断的两大问题——「结构单一」与「闭环断裂」——已通过 P0 规划 + 家校沟通专项方案得到解决：AI 建议将落为跟进任务、随访将有到期提醒、学生档案将开放教师写入口、审批将补上销假与统计，家校沟通也补齐了"学校—家庭"这一环。

但解决"闭环"只意味着流程能转起来，不代表特色立得住。当前仍有两个短板：数字教育停留在"几个分散的 AI 按钮"，没有形成统一的数字化育人闭环；辅导员个人成长则几乎是空白，教师端没有任何"我"的数据。这两点恰恰是最能体现产品差异化的地方，本版报告将其列为重点。

已解决 · 闭环

流程已经能转起来

P0 六项 + 家校沟通专项，补齐了"执行—反馈—沉淀"三环，教师端不再是"点一下就走"的事务台。

仍不足 · 数字教育

AI 是"散点"，不是"底座"

四个 AI 能力各自为战，没有统一入口、没有学情数据底座、没有教学分析闭环，教师感受不到"数字化"。

仍不足 · 辅导员成长

教师端没有"我"

无成长档案、无工作案例沉淀、无能力评估与激励。辅导员的工作与成长无法沉淀、无法被看见。

2闭环诊断：从断裂到闭合

把"闭环"定义为五个环节：感知 → 决策 → 执行 → 反馈 → 沉淀。初版盘点发现流程普遍断在后三环；经 P0 规划与家校沟通专项补齐后，后三环已全部有了落点。

状态更新（v2）：初版报告指出的 8 处断点，现已全部纳入规划——执行环由「统一待办层 + AI 建议转任务」补齐，反馈环由「随访到期提醒 + 请假销假确认」补齐，沉淀环由「学生档案教师写入口 + 审批统计归档 + 家校沟通台账」补齐。

2.3 根因归纳

  1. 定位偏差：教师端被设计成"学生管理的延伸"，而非"教师自己的工作台"。所有信息组织方式都以"学生"为主语。
  2. 缺少任务层：系统有"数据层"（档案/预警）和"建议层"（AI 分析），但中间缺少"任务层"——没有 TeacherTask 这类统一待办模型把两者串起来。
  3. 缺少记录层：教师的工作过程（谈心、家访、评语、互评）没有任何落点，导致工作无法沉淀、无法复盘、无法计入工作量。
  4. 闭环靠人而非靠系统：随访、销假、跟进这些环节，系统只提供字段，不提供提醒与驱动。
v2 视角：上述四条根因中，任务层与记录层正在补建，闭环问题已基本解决；但第一条"定位偏差"仍未根治——教师端的主语依然以"学生"为主，指向"教师自己"的两块内容（数字化的教学生产力、教师个人成长）依然缺席。这正是第 5 节要专门处理的问题。

4专项方案：家校沟通（家长观察者）

补齐"学校—家庭"这一环。约束是零家长端、零家长账号、无双向联动——家长在系统中是学生档案上的联系人实体，沟通由教师在教师端发起与记录。

定位："观察者"体现为被同步信息的对象，而不是"能登录系统的人"。因此不存在家长登录、家长自助查询与家长回执；沟通是单向的，教师端负责发起、记录与留痕。

4.1 已锁定的设计决策

决策状态：本节 10 项设计（A1–A10）已逐项确认，以下为定稿结果。
  • A1 家长身份纯联系人档案（guardians），6 个字段：student_id / name / relation / phone / is_primary / remark；无账号、无登录、无家长端
  • A2 台账字段场景固定五类（学业反馈 / 行为表现 / 请假告知 / 关怀约谈 / 日常沟通）；渠道 sms / report / link / note；状态 sent / pending / failed / draft
  • A3 分享链接表6 个字段：log_id / token / expires_at / revoked / view_count / last_viewed_at（二期）
  • A4 短信尺度只发"提示 + 引导"，如"【学校】X 老师就 XX 同学的情况与您沟通，请回电"——不含具体细节
  • A5 报告内容基本信息 + 沟通事项、请假记录；预警 / 关怀摘要逐次手动勾选、默认不含
  • A6 链接策略7 天有效、可撤销、只读、限流
  • A7 记录权限班主任与管理员可增删改，删除为软删除，保留审计痕迹
  • A8 请假告知提示时机 = 学生提交申请时；内容随发送时机变（审批前"已收到申请，正在审批"，审批后"结果 + 返校时间"）
  • A9 危机约谈干预记录新增"约谈家长"类型，并同步生成一条沟通台账
  • A10 安全策略三条全做：手机号脱敏 + 危机类禁分享 + 每条记录强制留痕

5本期重点：数字教育与教师个人成长

这两个维度是初版报告里覆盖度最低、也最难被同类产品复制的地方。它们的共同问题是：教师端没有把"教师"当作第一人称主语——数字教育停在"给教师几个 AI 工具"，教师成长则完全没有承载。

为什么"不突出"？数字教育不突出，是因为 AI 能力散落在四处、没有统一身份、没有数据底座，教师感受到的是"几个按钮"，而不是"我的教学被数字化了"；教师成长不突出，是因为它根本不存在——教师端没有一个页面属于教师自己。

5.1 数字教育：从"AI 散点"到"数字化育人闭环"

现在的 AI 是"外挂工具"：绵小城在独立页面、请假分析在审批页、班级分析在首页，彼此不通、结果不落库。要让它成为"数字教育"，需要补三个层次。

L1
统一副驾入口 —— AI 从"一个页面"变成"贯穿工作流的副驾"

把 AI 能力组件化为可嵌入的副驾，在审批页、档案页、预警页、成长页就地可调用；输出结果可直接"采纳为记录 / 转为任务"，而不是停留在对话框里。

L2
学情数据底座 —— 让画像、预警、教学分析有统一数据源

当前各类数据散落在业务表中，AI 每次现拼 prompt。引入标准化学情事件记录，为画像、预警、教学分析提供统一数据层。

L3
学情分析闭环 —— 从"统计图表"到"风险点 + 建议 + 效果回流"

学业 / 行为 / 心理数据 → 风险与薄弱点识别 → 辅导策略建议 → 效果回流验证。这是"数字教育"真正区别于"几个 AI 按钮"的地方。

5.2 教师个人成长：从"空白"到"成长可见"

这是初版覆盖矩阵里唯一全空的一行，也是调研中所有成熟开源校园系统都没有专门模块的行业空白——做出来就是差异化。它需要三块内容。

成长档案（e-Portfolio）

把 Mahara 的 e-Portfolio 范式移植到辅导员场景：工作案例、荣誉、培训研修、工作研究成果，按"证据 → 反思 → 展示 → 评价"组织，并可导出成长报告。

匿名工作问卷互评

辅导员之间匿名互评 + 学生对辅导员的匿名评价：按学期 / 主题发起问卷，结果只呈现聚合分布与匿名建议，不回溯到个人，形成"被听见、可改进"的成长反馈环。

能力与激励

能力框架 / 量规评估 + 成长积分与徽章墙，让成长可衡量、可激励；工作量统计（审批数 / 关怀数 / 任务数）让付出被看见。

成长看板

四个区块：成长轨迹时间线（档案事件自动成线）、能力雷达（对标辅导员九项能力）、工作量统计（审批 / 关怀 / 任务数趋势）、徽章墙与成长积分——教师端第一个真正"属于教师自己"的页面。

5.3 两个维度的交汇点

关键洞察：数字教育是手段，教师个人成长是目的——用数字化把教师成长变得可见、可衡量、可激励。两者一旦打通，就不再是"两张皮"：AI 学情分析的结果会自动沉淀为成长档案里的"工作案例"；问卷互评的聚合得分会自动更新能力雷达；教师的工作量会自动累计成成长积分。这样，"在工作中成长"才真正成立，而不是又加一个孤立的模块。

7结语

初版报告的两个判断——「结构单一」与「闭环断裂」——都已经落到实处：闭环有了规划，家校沟通有了方案。但这一版要提醒的是，闭环只解决"能用"，解决不了"突出"。

数字教育与教师个人成长之所以"不突出"，根子在同一个地方：教师端仍然没有把"教师"当作第一人称主语。数字教育目前是"给教师几个 AI 工具"，而不是"把教师的教学数字化"；教师成长则完全没有承载，教师端没有一个页面属于教师自己。

这两件事其实是同一件事：数字教育是手段，教师成长是目的。当 AI 学情分析的结果能自动沉淀为成长档案的工作案例、问卷互评的聚合得分能自动更新能力雷达、工作量能自动累计为成长积分时，"在工作中成长"才真正成立。到那时，教师端才从一个"管学生的事务台"，变成一个"教师愿意每天打开的成长平台"。

而调研显示，成熟的开源校园系统普遍没有独立的"教师成长 / 互评"模块——这意味着这条路没有现成答案可抄，但正因如此，它也是这个项目最有辨识度的机会。
