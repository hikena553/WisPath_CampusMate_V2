# MianMate 未实现功能清单（对照启智杯赛题）

> 分析对象：`mianyang-campus/`（FastAPI + Vue3 工程）
> 对照标准：`docs/赛题要求.md`（学生自助服务与校园事务智能助手开发任务）
> 生成日期：2026-08-06
> 结论一句话：**工程质量扎实，但产品重心跑偏了赛道——现有系统是「学生成长档案 + 辅导员管理平台」，赛题要的是「校园事务工单闭环平台」。**

---

## 〇、最重要的一个判断（先看这个）

现有项目的能力密度集中在这三块，而**它们都不在赛题的七项核心要求里**：

| 现有强项 | 代码体量 | 赛题是否要求 |
| --- | --- | --- |
| 学生成长档案 / 技能画像 / 5 维评分 | `growth.py` + `profile.py` + `GrowthPage.vue`(1046 行) | ❌ 不要求 |
| 心理危机预警与干预 | `crisis.py` + `crisis_service.py` | 🟡 仅"心理支持入口"擦边 |
| 教师/辅导员管理工作台 | `teacher.py`(506 行) + `teacher/HomePage.vue`(1107 行) | ❌ 不要求 |
| 课表 / 成绩分析 | `SchedulePage.vue`(1646 行) + `grade_analysis.py` | 🟡 仅"学业咨询"擦边 |

而赛题真正的主干——**工单全生命周期闭环**——恰恰是全项目最薄的一块：`backend/app/api/service.py` **只有 62 行**，是全部 19 个路由里最短的文件之一。

**这不是"再补几个功能"的问题，而是"主线要重建"的问题。**

### 要求 4｜全流程进度追踪与双向反馈闭环 🔴 最致命

赛题：  提交 → 受理 → 处理中 → 已转交 → 需补充材料 → 复核 → 办结 → 评价

`models/service.py:15-18` 全部内容：

    APPROVED = "approved"

| 赛题要求 | 状态 | 证据 |

## 五、建议的补齐路线

**第一梯队（1-2 天，性价比极高）**
先做 4 个"极小"项：接入通知调用、修复越权漏洞、修复 AI 回复未落库、撤销改软状态。**几十行代码就能让"闭环"和"数据留存"两项要求从不及格变及格。**

**第二梯队（3-5 天，主线攻坚）**
工单状态机 + 流转日志 + 评价体系 + 智能分流 + 前端时间轴。做完这一梯队，**项目级的"完整业务闭环"就真正达标了**。

**第三梯队（3-5 天，拉开差距）**
宿舍报修 + 失物招领两个场景 + 工单数据看板 + 向量 RAG + 学生自治角色。

**第四梯队（1-2 天，交付材料）**
Dockerfile + docker-compose + nginx + 部署手册 + 测试报告 + 项目说明书 + 演示视频。**这些是项目级的硬性提交要求，缺一项就掉级，别等到最后。**
