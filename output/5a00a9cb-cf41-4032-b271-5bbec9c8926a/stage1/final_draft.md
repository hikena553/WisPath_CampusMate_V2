# 智慧校园 AI 服务平台（WisPath CampusMate）功能介绍

## 一、平台定位

智慧校园 AI 服务平台（WisPath CampusMate，中文昵称"绵小城"）是面向绵阳城市学院师生建设的一体化校园服务系统。它把原本分散在教务、学工、办事大厅、消息群里的琐碎入口，收拢到一个统一的入口中，用"对话"作为主要交互方式，让学生查得到、问得准、办得顺，让教师看得清、批得快、跟得住，让管理者一屏掌握全局。

平台不是把线下流程简单搬到线上，而是围绕三件事重新组织：

- **把信息变成答案**：课表、成绩、通知、办事流程、校内规章，都通过校园知识库与大模型检索直接回答，而不是给一堆链接让人自己翻。
- **把问答变成办事**：对话不只是聊天，助手可以调用业务工具，直接创建请假单、提交办事申请、登记成长记录、查询成绩、写入学习计划，回答之后事情已经办完。
- **把记录变成画像**：学生的荣誉、竞赛、实践、论文、成果被结构化沉淀，折成五维评分；教师的关怀、审批、家访被留痕，成为决策依据。

平台采用前后端分离架构，共设学生、教师、管理员三类角色，同一套账号体系与权限模型下，各自进入自己的工作台。

## 二、核心能力

平台的能力可以归纳为四个支柱：AI 对话、成长画像、学业办事、关怀预警。

### 2.1 AI 对话：能问、能看、能听、能办事

AI 助手"绵小城"是平台的统一入口。它的能力不止于文字问答：

- **流式回答**：基于 SSE 逐字返回，提问后一到两秒就开始出字，不必等整段生成完。
- **深度思考**：遇到需要推理的问题（成绩趋势、课表冲突、成长短板分析），可切换深度思考模式，先给分析过程再给结论。
- **语音通话**：支持实时语音对话，语音识别与语音合成在一条 WebSocket 通道内完成，适合走路、排队等不方便打字的场景。
- **看图理解**：可以上传图片，由视觉模型识别内容。奖状、证书、通知截图都能直接读，省去手动录入。
- **知识库检索**：校内办事流程、规章制度、常见问题经过切分与向量索引，回答时先检索再生成，答案能对上学校自己的规定，而不是泛泛而谈。
- **工具调用**：助手背后挂了 54 个可调用工具（学生端 29 个、教师端 25 个），覆盖请假、办事、成绩、课表、成长记录、学习计划、失物招领、社区发帖、资源检索、求助提交、定时任务等。用户说"我明天发烧要请一天假"，助手会提取起止时间、事由、类型，生成请假单并说明提交给了谁。
- **对话管理**：会话可重命名、置顶、归档、软删除与撤销，支持按关键词搜索，长对话按"项目"组织，学生可以把一学期的选课咨询放在同一个项目里持续追问。
- **定时任务**：可以用自然语言约定周期性提醒，例如"每周一早上提醒我看本周课表"，任务可启停、可立即执行。

### 2.2 成长画像：让变化看得见

学生在校四年的成长，往往散落在奖状、照片、系统导出表里，毕业时难以整理。平台的成长档案把这件事结构化：

- **五类成长记录**：荣誉、竞赛、实践、论文、成果，每条记录包含时间、级别、主办方、证明材料。
- **五维综合评分**：把记录折算为学术素养、创新能力、实践能力、社交素养、综合素质五个维度，用雷达图呈现，学生自己能看到强项与短板。
- **技能与兴趣标签**：形成可检索的个人名片。
- **作品集**：把项目经历、证书荣誉、个人简历汇总成一份可直接分享的展示页。
- **材料档案**：证件、证明、成绩单、学籍材料集中归档，办事时不必再翻相册找扫描件。
- **教师侧成长档案**：教师的工作案例、荣誉、培训研修、研究成果同样沉淀，可导出成长报告。

### 2.3 学业办事：一屏之内办完

学生端把高频学业事务整合进"学业中心"，用六个标签页承载：课表、成绩、成长轨迹、请假服务、学习计划、AI 助手。

- **课表**：按周查看课程安排，支持调课与冲突提示。
- **成绩与 GPA**：查询各科成绩、绩点与排名区间。
- **成绩分析**：按学期、按课程类别看趋势，定位拉分科目。
- **请假与证明**：提交请假申请、查看审批进度、下载证明；办事服务在同一入口提交。
- **学习计划**：把目标拆成阶段任务，打卡闭环。
- **自习室**：番茄钟专注计时，统计今日与历史专注时长。

请假、办事、报修一类的申请统一进入审批中心。审批侧既有聚合多类申请的待审视图，也有可配置的流程引擎（流程定义、发起、审批、驳回、撤销），不同事由可以走不同链路。

### 2.4 关怀预警：把风险看见在前面

这是平台与普通校园 App 差别最大的一块：

- **情绪记录**：学生可以记录每天的心情，形成个人情绪台账；通话场景下的人脸情绪识别作为辅助信号记录下来。
- **对话语义识别**：系统对学生与助手的对话做风险识别，结合关键词与大模型语义判断，给出正常、轻微、中等、严重四级结果。
- **自动派单**：命中规则后自动生成教师待办任务，按等级推送，教师在自己的工作台里能看到"谁、什么时候、因为什么"。
- **处理闭环**：教师在心理预警工作台受理、记录谈话、标记处置结果，全过程留痕，管理员在危机监控页看全校分布。
- **家校沟通**：教师可为家长生成一条只读分享链接，家长无需注册账号，凭链接查看孩子在校情况；家访记录与沟通台账一并沉淀。

需要说明的是，预警是辅助手段，用于提醒教师"这个学生可能需要关心"，不替代专业的心理评估与干预。

## 三、学生端功能

学生登录后进入首页，主要功能如下：

| 功能模块 | 说明 |
|---|---|
| AI 助手 | 文字、语音、图片多模态提问，可调用业务工具直接办事 |
| 学业中心 | 课表、成绩、成长轨迹、请假服务、学习计划、AI 助手六个标签页 |
| 成长档案 | 五类记录、技能标签、五维评分雷达图 |
| 作品集 | 项目经历、证书荣誉、个人简历汇总展示 |
| 材料档案 | 证件、证明、成绩单、学籍等材料归档 |
| AI 资源空间 | 学习资源、行业资讯、校园信息统一浏览，支持收藏与 AI 推荐 |
| 交流社区 | 发帖、评论、点赞、关注、私信与群聊 |
| 失物招领 | 发布与检索失物信息 |
| 消息中心 | 会话、通讯录、论坛互动消息，支持搜索与建群 |
| 我的关怀 | 激励、关怀记录、家访记录的学生侧视图 |
| 求助 | 提交求助，由辅导员受理回复 |
| 反馈 | 对系统提出意见与问题 |

## 四、教师端功能

教师端定位是"随身的班级驾驶舱"，首页四张关键指标卡回答四个问题：我带多少学生、有多少假条待批、有几个心理预警、今天有什么到期。

| 功能模块 | 说明 |
|---|---|
| 班级概览 | 学生数、评分分布、成绩概况一屏看清 |
| 学生管理 | 名下学生列表、综合评分、成长档案与预警、请假记录 |
| 审批管理 | 请假与各类申请审批，支持批量处理 |
| AI 主动洞察 | 由系统主动生成的班级异常与个体变化提示，不必等教师去翻数据 |
| 心理预警工作台 | 分级预警列表、处置记录、跟踪状态 |
| 人文关怀中心 | 关怀日历、家访记录、正向激励发放 |
| 问卷互评 | 发起匿名问卷，聚合结果，不回传任何单条答卷 |
| 家校沟通 | 联系人管理、沟通台账、家长只读分享链接 |
| 待办任务 | 公共待办层，预警派单、审批、临时任务统一收口 |
| 教师成长档案 | 工作案例、荣誉、培训研修、研究成果与成长报告导出 |
| 消息 | 与学生实时通信，WebSocket 推送 |

## 五、管理端功能

管理端解决的是"全局看得见、规则管得住"：

| 功能模块 | 说明 |

| 组织架构 | 学院、专业、班级的层级维护 |

| 知识库运营 | 文档上传、切分、向量索引与问答语料维护 |
| 资讯与外部源 | 资讯源配置、AI 论文与开源项目等外部资讯聚合 |
| 课程表管理 | 学期课程、班级课表维护 |
| 危机监控 | 全校预警等级分布与处置进度 |
| 反馈管理 | 学生反馈的受理与回复 |

## 六、角色与权限

平台采用 JWT 认证与三角色隔离：学生只能进入学生端，教师只能进入教师端，管理员可巡视全部。前端路由按角色守卫，后端接口按角色校验，越权请求一律拒绝。敏感配置加密存储，上传文件做格式与大小校验，文件下载需登录鉴权。

## 七、适用场景

**场景一：新生入学与日常咨询。** 新生最常问的是"宿舍怎么走、选课什么时候开始、助学金怎么申请"。这类问题重复度高、答案相对固定，交给知识库问答最合适，学生不必打十几个电话。

**场景二：高频学业事务。** 查课表、查成绩、算 GPA、请假、开证明，都是每天发生的小事。平台把六件事收进一屏，学生少走三次入口。

**场景三：请假与审批闭环。** 学生提交、教师审批、结果回传、记录留档，全流程在线。教师不必在群里翻假条，学生不必反复问"批了吗"。

**场景四：学生关怀与风险预防。** 辅导员带几百个学生，靠印象判断谁需要关注并不可靠。情绪记录与对话语义识别提供线索，自动派单把线索变成待办，处置留痕让关怀可追溯。

**场景五：管理决策与运营。** 系统是否真的被用起来、知识库缺哪些内容、哪个学院预警偏多，管理端用数据回答，而不是凭感觉。

平台的能力与院校规模、专业设置解耦，除本校场景外，也适用于其他高校、中职院校、教育集团的同类需求；知识库与工具集可按学校实际业务替换。

## 八、使用方式

### 8.1 访问与登录

1. **访问地址**：通过学校统一发布的系统地址访问（具体地址以学校通知为准）。建议使用 Chrome、Edge 等现代浏览器的最新版本；系统同时适配手机浏览器，在手机上可获得接近原生应用的布局与操作。
2. **账号规则**：学生使用学号登录，教师与管理员使用工号登录，初始密码由学校统一发放。
3. **首次登录**：首次打开会先看到产品介绍页，点击进入登录页；输入学号或工号与密码，阅读并勾选用户协议后提交。
4. **进入工作台**：系统按角色自动进入学生端、教师端或管理端首页，无需手动选择。
5. **修改密码**：登录后建议立即修改初始密码；忘记密码可在登录页选择"找回密码"，完成身份核验后由管理员受理重置。

### 8.2 学生使用路径

- **想问事情**：直接在 AI 助手输入问题，例如"我这学期还差多少学分""补办学生证要什么材料"。问题越具体，答案越准。
- **想办事情**：在同一对话框里说明需求，例如"下周三到周五请事假，去参加竞赛"，助手会生成申请并给出审批人。
- **想看自己**：进入学业中心查看课表、成绩与成长轨迹；进入作品集整理项目与证书。
- **想被关注**：在心情卡记录状态，需要帮助时提交求助，辅导员会收到。

### 8.3 教师使用路径

- **每天先看首页**：四张指标卡确定今天先处理什么。
- **处理审批**：待批请假一键进入，逐条审批或批量处理。
- **关注学生**：在学生管理里按评分、预警、请假记录筛选，点开即看完整档案。
- **跟住预警**：在心理预警工作台受理派单，记录谈话与处置结果。
- **连住家长**：在人文关怀中心生成只读链接发给家长，家访与沟通写进台账。

### 8.4 管理员使用路径

- **看数据**：首页看板确认系统使用情况与异常。
- **管内容**：在知识库补充文档、在校验页确认索引生效，问答质量会随之变化。
- **管组织**：维护学院、专业、班级与账号，处理密码重置申请。
- **管系统**：在系统监控看服务与模型调用状态，在系统设置维护品牌与参数。

### 8.5 使用建议

- 提问尽量带上下文：说清时间、课程、事由，助手更容易一次做对。
- 涉及证明材料的场景，直接拍照上传，比手动填写更快。
- 长周期问题（选课规划、考研准备）建议建一个对话项目持续追问，历史上下文不会丢。
- AI 给出的结论以学校正式文件为准，重要事项请与辅导员或教务处确认。

## 九、技术架构与运行保障

平台采用前后端分离架构：前端为 Vue 3 + TypeScript + Vite + Element Plus，后端为 FastAPI + SQLAlchemy + Pydantic，数据库为 MySQL 8，迁移由 Alembic 统一管理。实时能力由 SSE（流式回答）与 WebSocket（即时消息、语音通道）分别承载，AI 能力接入通义千问系列模型，视觉与语音各用专用模型。

当前版本规模为：49 个可路由页面、52 个 API 模块、357 个接口、81 张数据表、54 个 AI 工具。系统支持一键启动，便于本地部署与演示；生产环境建议按学校安全规范配置独立数据库账号、关闭调试模式，并定期备份。

## 十、边界说明

- AI 生成内容基于知识库与模型推理，可能存在偏差，涉及学籍、成绩、奖惩等正式结论以学校文件为准。
- 心理预警为辅助提示机制，用于帮助教师及时发现与关心，不构成诊断，不替代专业心理服务。
- 系统中的个人信息按角色权限最小化开放，家长仅能通过一次性只读链接查看授权范围内容。
- 平台功能会随学校业务持续迭代，具体以线上版本为准。
